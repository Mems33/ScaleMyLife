# ScaleMyLife revamp: implementation plan

> For agentic workers: one implementer per phase, a reviewer per phase, the controller checks every phase in the browser on desktop and phone before the next starts. Steps use checkbox syntax.

Goal: turn the current app into a guided, content-first, game-flavoured productivity app without changing the engine, following `docs/superpowers/specs/2026-09-18-revamp-design.md`.

Architecture: plain files, no build. `styles.css` gets a token layer and restyled components; `index.html` gets the icon sprite and the Outfit font; `app.js` gets a compact header, five-tab navigation, a new Today, a six-step onboarding wizard, a smart add sheet and restyled views; `core.js` gets a pure `parseTask` helper and tests; the Edge Function gets one new tool in phase 9.

## Global constraints (copied from the spec, binding for every phase)

- No build step, no framework, no CDN scripts. CSP allows only `'self'` scripts and Google Fonts.
- `sw.js` `CACHE` bumps in every commit that touches a precached asset (`index.html`, `styles.css`, `core.js`, `app.js`, `gradient.js`, `cloud.js`, `manifest.json`, `privacy.html`, `terms.html`).
- `npm test` passes at every commit (three suites, chained with `&&`, all three must report `0 failed`). Migrate tests in the same commit; never delete an assertion without an equivalent, except the premium block in phase 2.
- ES5 in `app.js`, `core.js`, `cloud.js`. `esc()` on every user string rendered into HTML.
- No em dashes in code, comments, copy or commit messages. None of the banned words listed in the spec.
- Class names and ids in inventory section 10 stay unless the phase says how they migrate.
- Six themes keep working. Check Daylight (light) as well as Dungeon.
- Commit message style: short summary line, a body that says what changed and why, then the trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Stage only the files the phase touched, never `git add -A` (CLAUDE.md is modified in the working tree and must not be staged).
